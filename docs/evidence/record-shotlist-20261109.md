## 硬规格

- **32 秒 / 30fps / 960 帧**，2272×1396 或 1920×1080；真实运行画面，不是静帧、不是概念图。
- 按主仓库已入账的 M2 口径：30–60 秒、≥24fps、含完整叙事弧。旧 `demo-video-hd.mp4`（8.1s / 10fps）不达标、剪不掉也补不齐；**2026-11-09 21:54 已按本脚本重录完成**：`docs/demo-video-32s.mp4`（37.8s / 30fps / 1920×1186），逐秒 38 帧无废帧。本脚本留作后续重录的镜头规范。
- 程序化 SFX / BGM 同步收录；静音态也能玩。

## 相机纪律（上一版 16–35 帧废掉的根因，重点）

- 全程**固定机位或受控推轨**：禁止鼠标自由旋转、禁止爬升、禁止贴近近景几何体。
- 角色保持完整入画，屏高占比约 36%；任何近景模型不得糊住镜头。
- **霓虹街道必须始终在画**，街道出画即该段作废。
- 开录前跑一次相机诊断，确认相机与近景 mesh 距离；每段结束回安全机位。

## HUD：脏玻璃（唯一写法）

**全部数值以 `hud-glass-spec-20261109.md` 为准**（同目录），本节只给方向，别在这里另记一套参数。

底子保持硬——黑底、黄黑警戒带、硬边斜切、非对称圆角；玻璃只承载信息层（计时、失衡条、接力提示）。

- 实底 `rgba(4,6,12,.62)`（实测 ≥4.5:1）、T0 模糊 `blur(18px) saturate(1.35)`、1px 奶黄描边、非对称圆角、顶部黄黑警戒条，玻璃内叠扫描线与 Ben-Day 网点。
- 文字用纯色坐在实底上，**不直接坐在模糊背景上**（否则对比度随 3D 画面飘，WCAG 过不了）。
- 高光与闪光 ≤3 次/秒（`FLASH_LIMIT_PER_S = 3`，WCAG 2.3.1）。
- 实施前把主仓库 `vite.config.mjs` 的 `keepStandardBackdropFilter()` 插件搬过来，并按 `applyGlassBudget` 五档限真玻璃层数——v3 当前 2107 mesh / 551 draw call，多层真玻璃会掉帧。不搬插件的话玻璃会**静默失效**（Chrome 154 不认 `-webkit-` 别名），控制台还不报错。

## 交付前自检

1. `ffprobe`：时长 30–60s、`r_frame_rate` ≥24、无超过 10 秒的静帧段。
2. 每 3 秒抽 1 帧，逐张过判定卡：奶蛙家族里的一只 + 录像带漫画语汇 + 无任何具体权属素材。
3. 家族：至少 4 只剪影可辨；闪光 ≤3 次/秒。
4. 相机：全程街道在画、角色完整、无近景糊镜头；对照 `frame-audit-20261109.md` 里那段废帧，别重演。
5. 视频与报告书口径一致（团队、赛事名、冻结基准），别出现第二套名字。
