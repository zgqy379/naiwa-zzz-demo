## 这些失败是怎么来的

测试在无头浏览器 + 软件渲染（swiftshader）环境下运行，存在两类环境失真：

1. **逻辑时间走极慢**：实测连按 12 次攻击，游戏内计时仅推进约 0.6 秒，帧率远低于本地真机。凡依赖"等 N 毫秒后动画应推进"的时序断言，在该环境下天然易抖。
2. **对手位置未对外暴露**：当时 `window.__npr.opponent` 只有 `{hp, maxHp}`，没有 `group.position`，测试脚本无法取到真实距离，无法判断"该走近多少才能进攻击范围"，距离类用例（移动、空格攻击、连段推进）因此误判。

## 复核结论（2026-11-10 00:26 实测）

改用本机 Chrome + playwright-core 真实驱动页面，进入战斗后模拟操作，结果：

| 检查项 | 实测 |
|---|---|
| 伤害累积 | `damageDealt` 21 → 57，对手 HP 200 → 143 |
| 命中计数 | `hits=3`，每次命中均扣血 |
| idle 动画推进 | `idlePhase` 3.635 → 3.745，`advanced=true` |
| 连段推进 | `stageIndex` 0 → 1，`inCombo=true` |

即：上述失败项所对应的功能**实际可用**，失败系测试环境失真所致，而非产品缺陷。

## 附：关于"结算 0 伤害"

同批测试中 `05-result.png` 显示"造成伤害 0 / 最大连击 0"，原因是该用例用 `window.__npr.opponent.hp = 0` 强制触发结算，**不经过真实打斗**，属用例设计使然而非 bug。凡引用该截图推断"实战打不出伤害"的结论均不成立，应以真实驱动测得的 `damageDealt` 为准。
