## 0. 结论速览（TL;DR）

1. **绑骨对这 16 只已经是「已完成时」，不是课题**。2026-11-12 深度改造线已用官方 Lux3D 链路给 16 只全部装上 52 关节 Mixamo 骨架；本轮我亲测 `compare-skeletons.mjs` 确认跨角色骨架完全一致（含 15 根手指骨）。真正的缺口是**动作库窄（85 选了 20）+ 逐角色动作映射缺失（16 招全播剑击）**。
2. **官方动作库里躺着一批「零成本白捡」的救命片段**：我从官方 OpenAPI 枚举里抓出全部 85 个动作 ID——`Hit_Knockback`、`Hit_Head`、`Jump_Start/Loop/Land`、`Slide_Start/Loop/Exit`、`Melee_Hook`、`Punch_Cross`、`Sword_Block`、`Dance_Loop` 等**都存在但没打进共享库**。重打一次库（6 积分/段）就能修掉「STAGGER 永远回退 Hit_Chest」和「受击无方向性」两个已登记缺陷。
3. **Mixamo 路线对本项目是「零映射成本」**：官方绑骨产物骨架名就是 `mixamorig:*` 52 关节标准骨架——Mixamo 动画 FBX 下载后在 Blender 里**不需要骨骼映射**（02 §3.3 阶段 C 整段跳过），是官方 85 动作不够用时的免费无限扩容源。Mixamo 不吃 GLB，须 Blender 转 FBX 中转（三源确认）。
4. **「找图重做」只该作为个体手术，不应全家重来**：硬前提是参考图本身接近 T-pose（roster.json 的提示词模板已把 T-pose 写成硬约束，选图同理）；单视角图生 3D 有实测质量风险（本项目 3D 手产物就是「侧视手 + 空心袖口」，我看了 preview.png）；官方 img-to-3d 支持 **1–32 张多视角输入（G1-Turbo）**，是降该风险的正解。
5. **外部自动绑骨工具（Anything World / Meshy / Tripo）在本项目受台账红线约束**：`docs/ASSET-LICENSES.md:98` 固定口径「3D 资产一律官方工具生成」、`:115` 明令不得把外部工具写成官方。它们只能作为「未来新增形态特异角色且官方绑骨失败」的预案，启用前须制作人改口径并登记。
6. **「没手脚角色」前提已过期**：05 盘点证实 16 只重建后**全部是人形四肢造型**。真正的「准无手脚」是三只特肢个体——蛋形（奶蛋/奶豆/豆奶）、翅手（奶鸡）、鳍（奶鱼）——解法不是重新做模型，而是**逐形态的动作映射 + 程序化附加层**（ZZZ 邦布的弹跳/滚动语言 + squash & stretch 十二原则，见 §六）。

### 2.1 链路全景与计费

`scripts/lux3d/pipeline.mjs:4-15` 头注释登记的完整链路（全部走 Aholo 官方 OpenAPI，网关 `api.aholo3d.cn`，文档 `labs.aholo3d.cn/api-docs`）：

| 步骤 | 端点 | 计费（脚本注释） | AGENTS.md 交接登记 | 说明 |
|---|---|---|---|---|
| ① 文生 3D | `POST /lux3d/v1/generate/text-to-3d/task/create` | 13 积分/只 | 20 积分/只 | 两处登记不一致，以官方控制台实时价为准 |
| ①′ 图生 3D | `POST /lux3d/v1/generate/img-to-3d/task/create` | — | — | 支持单图 `img` 或 1–32 张多视角 `imgs`（本轮 curl 官方 OpenAPI 证实） |

| ③ 动画重定向 | `POST /lux3d/v1/animations/retarget/task/create` | 6 积分/段 | 6 积分/段 | 单次 1–10 段，官方 85 段枚举 |

### 2.2 硬约束清单（踩过的坑，逐条有出处）

1. **绑骨输入必须 T-Pose / A-Pose**，否则报 `MODEL_NOT_RIGGABLE`（pipeline.mjs:8-9、15；roster.json `_note` 把它写成了提示词硬约束）。
2. **输入必须是公网 HTTPS GLB**（官方 OpenAPI `modelUrl` 字段描述；本地文件先走 Asset 上传接口）。
3. **任务产出 URL 有效期 2 小时**，拿到就落盘（pipeline.mjs:13-14）。
4. **retarget 单次最多 10 个动作**，`animationIds` 从 85 个枚举里选、区分大小写、不可重复（pipeline.mjs:10 + 本轮 OpenAPI schema 原文「从以下 85 个可选值中选择 1–10 个」）。两库拆分正是这个限制的产物（build-animlib2.mjs:4-9）。
5. **并发上限**：批量时要对 `CONCURRENCY`/`GENERATION_CONCURRENCY_LIMIT_EXCEEDED` 报错做等待重试（batch.mjs:57-60；OpenAPI 错误码证实）。
6. **combined 模式产出的片段名是 `animation_1..N`**（按传入顺序），必须本地改名（finalize.mjs:4-6、41-45），否则游戏侧没法按名查片段（clips.mjs:50-54 的 byName 机制依赖可读名）。
7. **`Animation.dispose()` 不清采样器 accessor**——剥离动画时必须显式释放，否则角色文件反而更大（finalize.mjs:104-120 注释登记实测「10 段动画留下 1000+ 个 float accessor」）。
8. **局部单位 ≠ 世界单位**：官方绑骨网格写在绑定空间、绑定矩阵带缩放（实测差 6.17 倍且逐角色不同）——任何以局部单位表达的新东西（描边宽、挂骨武器、粒子偏移）都要先除以累计缩放（AGENTS.md 交接 19:6x 风险 3；`src/core/scale.mjs` 统一处理；weapon.mjs 的「0.62m 锅铲变 2m 巨铲」即此坑）。

## 三、路径 B（课题原 ① 后半）：Mixamo 路线 = 官方动作库不够用时的零成本扩容

### 3.1 Mixamo 的输入要求（≥3 源交叉验证）

| 事实 | 来源 |
|---|---|
| 只接受 **FBX / OBJ / ZIP** 三种上传格式，**不支持 GLB/glTF**；FBX 要勾 Embed Media、OBJ/ZIP 要带贴图 | Adobe 官方 rigging 指南（helpx.adobe.com）；Facebook Answers「does-mixamo-support-glb」；nhance-school 排障指南 |
| 模型须**人形**、处于（或接近）**T-pose**，非 T-pose 会导致关节错位/绑骨失败；上传后在模型上打 7 个关节标记点（下巴/双腕/双肘/双膝/裆） | Adobe 官方指南；WhatMakeArt 教程（02 §3.3 已引）；RebusFarm 指南 |
| 社区流传单文件上限约 **60 MB**（Adobe 官方帮助页只写格式不写上限，60MB 为社区口径） | nhance-school 及浏览器替代工具宣传页（以「无上限」反衬 Mixamo 有上限）——**标记：非官方数字** |
| 完全免费（Adobe 账号），无官方 API，浏览器操作 | Mixamo 官网；02 §3.3 |

对本项目：**Mixamo 的「自动绑骨」这半边用不上**（官方链路已给出更好的、跨角色一致的骨架），用得上的是它的**动作库**（数千段免费人形动画，支持调速度/手臂空间后下载）。

### 3.2 本项目的特殊性：骨骼映射整段跳过

02 §3.3 的「阶段 C：Blender 中重定向到自定义骨架」要建骨骼映射/Rokoko/约束——**本项目全部跳过**：官方绑骨产物的骨架名就是 Mixamo 标准名 `mixamorig:*`，且本轮亲测三份 GLB 骨架完全一致（§1.1②）。因此：

- Mixamo 下载的动画 FBX（**Without Skin** 档）导入 Blender 后，其骨架与角色 GLB 的骨架**同名同层级**；
- 把动画数据拷贝（或直接把 Mixamo FBX 的 Action 烘到目标骨架——同名骨连约束都可以省）后导出 GLB；
- three.js 侧零改动：动画轨道名 `mixamorig:Hips.quaternion` 直接命中现有模型节点，走现有 ClipDriver/共享库机制（§2.4）。

唯一要盯的就是 **FBX 轴向与 0.01 缩放**（Mixamo FBX 经典坑，02 §3.3 阶段 C 第 10 条、Adobe 社区「Blender 导出 FBX 上传 Mixamo 失败」帖双向都踩这个）——导入/导出时统一按 Blender glTF 导出器的默认轴向处理，并在 finalize 口径里量化。

### 3.3 操作步骤（与 02 §3.3 的差异点加粗）

1. `Blender` 导入角色 GLB（File → Import → glTF 2.0）——**角色文件用 `--no-animations` 版本**（16 只现役 runtime 文件本身就是 0 动画纯骨架+网格，直接可用）。
2. 导出 FBX（默认 7.4 二进制、Path Mode=Copy+Embed Textures）→ 上传 Mixamo——**本项目角色已经是 Mixamo 骨架，Mixamo 会识别「已绑骨」直接跳过打点向导**（同名骨架免绑）。
3. 动画库里挑动作（受击类搜 hit / knockback / stumble；战斗类搜 punch / kick / slash），调 Speed 预览。
4. 下载 FBX，选 **Without Skin**。
5. Blender 导入该 FBX → **因骨架同名，Action 直接可用**；必要时 Bake Action 落关键帧。
6. 多段动作进同一 GLB：NLA 轨道合并或逐段导出后用 @gltf-transform 合并（**复用现成 `finalize.mjs --actions` 改名+压缩**，与官方库同口径落盘）。
7. 导出 GLB → `compare-skeletons.mjs` 验骨架一致 → 进 `public/asset/` 或并入共享库 → ClipDriver 播放。
8. 校验：`pipeline.mjs inspect` 看 `animations` 数与 `clipNames`。

### 3.4 Mixamo 能补官方 85 补不了什么

官方 85 的受击只有 3 段、无方向性跌倒/踉跄变体、无空中受击、无四足/兽形动作。Mixamo 库的补充方向（按「战斗爽」优先级）：

- **受击族**：hit 到各部位变体、stagger/ stumble 踉跄、fall backward/forward 倒地、get up 起身——补齐「受击位移感」（05 盘点缺陷 4 的动画侧）；
- **攻击族**：拳击组合（jab/cross/hook/uppercut）、踢腿（kick 类）、肘膝——西格玛「硬汉铁拳」、奶鸡「啄击」需要的就是这些而非剑击；
- **个性待机**： dances / 鼓掌 / 抖腿等，给选人页 live3d 逐只配「性格待机」。

代价：零积分，但要人工过 Blender（每段约几分钟）+ 逐段核对骨架贴合。**定位：官方 85 打底（自动、便宜、风格统一），Mixamo 按单补缺（免费、人肉、风格需筛）**。

### 3.5 无 Blender 的两条捷径（备选）

- **BlenderMixamo2glTFConverter**（GitHub，Blender 3.6+ 脚本）：把 Mixamo FBX 批量转成「任意骨架可用的 GLTF clip」——半自动，仍要装 Blender 但免手工；
- **r/threejs 社区的 Mixamo Animation Merger**（2025 帖，纯 web 工具）：无需 Blender 直接把多个 Mixamo FBX 合成一个含全部动画的 web 优化 GLB——**未实测**，列为线索不背书。

## 四、路径 C（课题原 ②）：找图重做 = 更好的参考图 → 官方图生 3D → 绑骨

### 4.1 官方图生 3D 的能力边界（本轮 curl OpenAPI 证实）

`POST /lux3d/v1/generate/img-to-3d/task/create` 请求体：

- `img`：单图 URL；**`imgs`：1–32 张图片 URL 数组**（G1 / G1-Turbo，保留顺序、第一张为主参考；与 img 互斥）；
- `version`：G1 / G1-Turbo；`faceCount`：10000–300000；`outputFormat`（G1 固定 ZIP+GLB）；`enablePbr`（G1-Turbo 可出白模）；`aiPredictSize`。
- 客户端另有上游：`multimodal-to-image`（多模态生图）与 `image-to-four-view`（单图补四视图）端点（client.mjs:15-16）——**参考图不达标时可先在官方链路内「生图→四视图」再喂 3D**，不出官方口径。

### 4.2 单视角推断的质量风险（有实物证据）

§1.1④ 的 3D 手：单张俯视图 → 侧视手 + 空心筒袖口。AGENTS.md 交接 02:52 的处置是「姿态调到最佳可用角度但几何本身未重生成」，并给出正解线索：「若要重生成可用多视角输入」。台账另登记过同类折返事件：奶粉罐盖被 mask 抠掉、奶鱼左眼被抠、奶瓶透明奶嘴被抠——均「折返喂 raw」才过（ASSET-LICENSES.md:58/60/61）。**结论：单图重做必须配「生成→四视图/三选一→人工筛选→折返」的验收环，多视角 imgs 是第一优先手段。**

### 4.3 硬前提：参考图必须 T-pose（从 roster.json 迁移出的选图标准）

官方绑骨报 `MODEL_NOT_RIGGABLE` 的唯一形态原因是「非 T/A-pose」（§2.2.1）。图生 3D 的产出姿态**跟随参考图姿态**——参考图是跑姿/坐姿，产物就绑不了骨。选图五条硬标准（把 roster.json 的 `_pose/_tail` 提示词反向用作验收清单）：

1. 双臂水平展开成 T（或接近 A-pose 的 45° 下张）；
2. 全身入镜无遮挡、手脚可见（课题原话「有手有脚」的量化版）；
3. 纯色/干净背景（利于 mask 与轮廓推断）；
4. 三四分之一正面视角（正侧视丢失另一半形体信息，是 3D 手翻车的直接原因）;
5. 无手持道具（道具会被并入网格，绑骨后手部权重脏）。

现实矛盾：自然图库里摆 T-pose 的「奶蛙家族风」插画极少 → 实操上优先走 **官方 multimodal-to-image 按 roster 提示词重新生图**（生图即控姿态），而不是在现有采集图里「找」——这也顺带解决权属问题（生图产物权属口径与现有 16 只一致）。

### 4.4 IP 与台账三道关

1. **参考图权属**：现有 16 只的采集图（XHS/NETA 派生）全部「权属未核、仅内部过程证据」（ASSET-LICENSES.md:29/47-63、70）——新参考图若直接取自采集图，会复制同一个未闭合缺口；官方 AI 生图重绘路线（小奶蛙/奶豆/奶猫等 9 只已走的 route=redraw）是已登记的合规先例。
2. **家族风格统一**：16 只现役风格 = roster `_note` 的「潮酷街头 + 卡通渲染」+ 统一 G1 版本 + 统一 `_style`。任何重做单只都要过「4×4 花名册拼图并排不违和」验收（现成工具：`scripts/lux3d/roster-sheet.mjs` 产出 `v3-roster-sheet-*.png`）。
3. **台账登记义务**：新 GLB 入 `docs/ASSET-LICENSES.md` 主表（平台生成物行式），`MODEL_NOT_RIGGABLE` 等失败事件与积分消耗按改动记录惯例登记。

### 4.5 操作步骤与验收门槛

```
① 生图（官方 multimodal-to-image，提示词 = roster 模板 + 目标角色 distinctive）
   → 3 选 1 筛图（对照 §4.3 五条硬标准）
② （可选）image-to-four-view 补四视图
③ img-to-3d：优先 imgs=[正视,侧视,背视] 多视角（G1-Turbo），faceCount 30000 对齐家族
④ pipeline.mjs inspect 基础结构 → node scripts/lux3d/pipeline.mjs rig --name X --model-url <公网URL>
⑤ retarget 全套 10 段 → finalize → compare-skeletons 验一致
⑥ roster-sheet.mjs 拼图过风格关 → 游戏内实机截图过 NPR 材质关（武器异步补 applyNpr 的坑见 AGENTS 22:0x 交接）
```

验收门槛：rig 不报 MODEL_NOT_RIGGABLE；52 关节与现役一致；贴图 512JPEG 后体积 418–558KB 量级；花名册拼图无明显风格跳出。

### 4.6 16 只里谁值得重做（判定）

**当前没有一只必须重做**（§六给全部 16 只的在现役模型上的定制方案）。重做仅在三情形下启动：①某只的现役网格在某个必需动作上穿模严重且程序化层救不回（如奶蛋做深蹲类动作躯干与腿穿插）；②制作人主动要求提升某只的单体质量；③新增第 17 只家族成员。**优先级建议：不做。** 把积分花在 §2.5 的动作扩容（60 积分收 20 段）比换一只模型对「战斗爽」的边际收益高得多——05 盘点的结论「最大的空档不是骨骼而是个性」直接适用于「重做模型 vs 扩动作」的选择。

## 五、路径 D（课题原 ③）：绑不了骨的替代方案（成本从低到高）

### 5.1 定位

对本项目 16 只，「绑不了骨」**当前不存在**（全部已绑）。本节服务于：未来新增形态特异角色（蛇形/多足/球体）、官方 rig 报 MODEL_NOT_RIGGABLE 且换图不可行、或制作人对某只要求超出人形动作库的表达。按成本升序：

### 5.2 程序化伪骨骼（最低成本，零积分，零依赖）

对无 skins 模型（如官方生成的纯道具/建筑）或已绑骨架上做**骨架外附加运动**：

- **部位摆动**：模型按语义拆成多个 node（或对单 mesh 用骨骼链），代码逐帧写旋转——本项目已有成熟先例：武器拖尾 `src/vfx/weapontrail.mjs`（逐点切线×视线求侧向量）、`animation.mjs` 的 6 风格程序化层（slash/thrust/slam/spin/peck/lash，animation.mjs:174-317）；
- **顶点形变**：shader 侧 squash & stretch（对根矩阵或 uv 扰动），适合蛋形角色的挤压弹跳（§六.2）；
- **拖尾/飘带**：verlet 链模拟尾/鳍/耳的次级运动，挂在 `mixamorig:Head`/`Spine2` 等既有骨上（§六.3 直接可用此方案）。

成本最低、完全可控，但表达力上限低（无真实蒙皮形变），适合**次级运动与风格化夸张**，不适合承担主体动作。

02 §3.3 已给通用全流程（Rokoko 免费插件 / Auto-Rig Pro 付费 / 原生骨骼约束三条映射路径 + Bake Action 烘焙）。对本项目的增量提示：

- 手动绑骨后**刻意把骨架建成 mixamorig 52 关节同构**（或绑完用官方 rig 反向比对），可继续免映射吃共享库；

## 六、准无手脚形态的定制战斗方案（逐形态，课题原 ④）

### 6.1 前提更正与总架构

05 盘点（§3 总判）：16 只重建后**全部是人形四肢造型**。本节按「形态特例」给方案，总架构统一为三层：

```
第 1 层  共享人形库（现役 20 段 + §2.5 扩容）→ 全员基底动作
第 2 层  程序化特肢层（新增代码）→ 尾/鳍/耳/裙/壳的次级运动，不进 GLB
第 3 层  逐角色招式映射（改 clips.mjs ACTION_CLIP 为按 id 查表）→ 「换壳即换招」
```

第 3 层是复活动画.mjs 程序化 6 风格的钥匙：`animation.mjs:122` 起 `if (this.clips) return` 让程序化层在 clip 模式下整层死代码——但它的 6 风格（slash/thrust/slam/spin/peck/lash）逻辑完好。**改法：把 6 风格从「替代骨骼动画」降级为「骨骼片段播放期间叠加的上半身/躯干偏移」**（additive 思想，02 §2.3），每只按 moves.mjs 的 16 招 style 选择风格层——用零积分换回「奶鸡啄、奶兔鞭、奶鱼甩」的可视差异。

### 6.2 滚撞型：奶蛋 / 奶豆 / 豆奶（蛋形大躯干，squad 档位 power）

**ZZZ 参照**：邦布（圆头圆脑小型机器人）的动作语言就是**弹跳入场、滚动、弹性待机**（知乎「诺姆动作设计」讨论：邦布自动跳入战场、待机小动作显调皮；Fandom/VG247/官网对其「bunny plushie 圆润机器人」的定位；YouTube 全邦布动画合集的观感共识）。圆形角色的物理语言 = **squash & stretch**（十二原则第一原则；Animation Mentor/Adobe/Instructables 多源：拉伸显速度、压扁显冲击、体积守恒）。

**具体方案**（现役模型上实现，不重做）：

- **移动/追击**：不播 Walk_Loop，改「**弹跳步**」——程序化层让根节点做抛物线弹跳（周期 ~0.4s），起跳瞬间 `mixamorig:Spine` 链纵向拉伸 1.08、落地压缩 0.92（shader/骨架混合实现），配合落地尘埃粒子；腿部骨骼仍播 Walk 但振幅压低（蛋形角色腿短，弱化腿的存在感）。
- **攻击（蛋滚冲击/滚撞）**：蓄力 = 压缩 0.85 + 下沉；冲刺 = 根节点绕前进轴**滚转**（模型自转 360–720°，rolling 动画的语言）+ 拖尾；命中 = 压扁 0.8 弹起 + 撞击星。滚转期间四肢骨架播缩起的 T-pose 变体（四肢贴身），观感即「蛋在滚」。
- **受击**：蛋形角色受击不用 Hit_Chest（剑击类后仰不贴形状），改程序化「**果冻抖动**」——Spine 链做 2–3 个衰减正弦的横向剪切 + 整体压扁回弹；重击才切 Hit_Knockback。
- **实现挂点**：全部在 ClipDriver 之外加 `squashLayer`（更新根节点 scale/rotation 与 Spine 链局部旋转），与 mixer 并行（mixer 写骨、层写根与附加偏移，互不覆盖——`animation.mjs` 已有「片段模式不写根变换」的门禁 122 行，本层走根 wrapper 而非 mixer 轨道，避开门禁）。

### 6.3 尾鳍/长尾型：奶鱼（尾鳍+背鳍）与奶鼠/奶狗/奶猫（尾链）

**参照**：ZZZ 邦布与小型敌人的次级运动共同点是「身体末端部件永远在动」（官网站「enn enn」走街声效 + 知乎入场/返场细节讨论）；动画工业的标准做法是**链式正弦衰减 + 速度耦合 + 惯性延迟**（12 原则的 follow-through/overlapping action，02 §2.5 已引）。

**具体方案**：

- **程序化尾链**（三只尾 + 奶鱼尾鳍共用一个模块）：从 `mixamorig:Spine2`（臀位）向下构造 4–6 节虚拟链（无实骨，直接对网格做骨骼级控制不可行——现役网格无尾骨，**尾是网格的一部分被 Spine/Hips 蒙皮**）。因此实际做法是**shader 顶点偏移**：以世界坐标高度/轴向为相位，对臀部以下顶点施加 `sin(phase + t·freq) × 衰减 × 速度系数` 的横向摆动——奶鱼按「鱼泳」参数（幅度大、频率低、随移速加速），猫/鼠按「竖尾平衡」参数（小幅高频）。**风险与前置**：需知道臀部顶点在网格里的分布——单 mesh 无语义分区（05 盘点 §2.1「mesh 名全是 geometry_0」），可按**顶点到 Hips 关节的距离权重**近似分区，先在奶鱼（尾鳍离主干最远）上试做。
- **战斗感接线**：奶鱼的「尾鳍横扫」= 上半身转体（复用程序化 lash 风格的躯干扭转参数）+ 尾链摆动瞬时增幅 ×3 + 横扫弧光特效（现成 SlashArc）；命中瞬间尾链反向鞭甩一次（overlapping action 的受击版）。
- **备选（若 shader 方案观感不足）**：走 §2.6 官方 articulation-animation 端点，用提示词「尾部摆动」生成动画后并库——**未验证，实验优先级低于 shader 方案**。

### 6.4 翅手型：奶鸡（翅端无五指）

问题：武器挂 `mixamorig:RightHand`（weapon.mjs:57-76），但奶鸡翅端蒙皮到手指骨的网格极少，握武器会悬空/穿模。

**方案**：①**不给奶鸡挂手武器**——改「翅刃」：翅端顶点在攻击时做程序化外缘拉伸 + 白刃光（贴武器拖尾模块的 ribbon 到翅端世界坐标，`activeWeaponTip` 已支持任意 node 查询 main.mjs）；②攻击映射全换拳脚族：`ATTACK_1/2 → Punch_Jab / Punch_Cross`（官方库现成）+ 程序化 peck 风格叠加「头部前倾啄击」（Head 骨前倾 25° 快速回弹）——「啄击三连」的招式名第一次有画面；③待机加「抖翅」微动作（双肩骨小幅快振，邦布式性格待机）。

### 6.5 迷障/裙装型：奶粉（粉裙 + 撒粉迷障，squad 档位 prop）

裙摆是腿部动作的天敌（05 盘点特例表）：**方案**是「上半身演、下本身藏」——①战斗移动用小碎步（Walk_Loop 变速 1.4×，程序化压低抬腿幅度），攻击片段选上半身主导的 Spell_Simple_Shoot / Punch_Jab（官方库现成）避免深蹲动作穿裙；②「撒粉迷障」本体演出 = 招式道具化：PropLayer 播放「抬手扬粉」程序化（双臂上扬 + 手腕抖动）+ 粒子系统（现成 SparkParticles 换粉白色 + 大颗粒低重力 + 长驻留）在身前生成半球迷障云，迷障即「技能可视体」；③裙摆本身走 §6.3 同款 shader 顶点摆动（按 Spine 高度分区，幅度小于尾链）。

### 6.6 大体量型：西格玛奶蛙（壮汉比例，1.15 缩放）

- 动作库换**拳法**：`ATTACK_1/2/3 → Melee_Hook / Punch_Cross / Sword_Heavy_Combo`（官方库现成，Sword_Heavy 作终结的重量感最强 4.33s）；全部片段播放速率**不再对齐快节奏窗口而是拉满**——西格玛的招应比全队慢 15%（重量感 = 慢 + 预备长，02 §2.5 十二原则）；
- 受击用 Hit_Knockback 而非 Hit_Chest（大块头被打退才有力量反差）；
- 待机换 `Idle_FoldArms_Loop`（官方库白捡，抱臂 = 硬汉人设，选人页 live3d 直接受益）；
- 程序化层：落步时地面微震（camera shake 复用 cinematic.onHit）。

### 6.7 ZZZ 邦布式「小动作清单」（全队通用的性格层）

多源共识：邦布的讨喜来自**入场跳入战场 + 待机调皮小动作 + 返场加速跑**（知乎诺姆讨论、Reddit「hilarious animations」帖、YouTube 全动画合集）。映射到本项目零成本可做的：选人页/登场各配一段白捡片段（Dance_Loop / Idle_Talking_Loop / Yes / Sitting 系列），战斗开场加「跳入场」（Jump_Land 白捡段 + 尘埃），回合间待机随机插 Idle_Talking_Loop 小动作——「仪式感」的最大单笔性价比（§八行动 3）。
