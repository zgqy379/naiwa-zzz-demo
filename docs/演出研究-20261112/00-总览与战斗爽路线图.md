## 一、制作人八问速答

### Q1 画面怎么运镜？（出处：01 档案 §1/§3/§5）

ZZZ 的运镜本质是**「强锁定 + 最小位移 + 不完全回正」**：镜头只在必要时移动必要的最小距离，停在能同时框住敌我的「三角区边缘」就停，绝不回到标准构图——这是它镜头动得多却不晕的原因（机核两篇全文交叉，01 §1.1）。命中瞬间用「拉近 punch（快起慢落）+ 震屏（避开 Roll 轴）+ FOV 收窄」三件套（01 §1.2）。五个演出段共用一条剪辑语法**「快进慢出」**：进场永远用闪/切/瞬时拉近（≤0.2s），演出内放慢，出尾用环绕+定格+消散（01 §1.6）。终结技是五拍结构：预期→切镜（黑场+招式名大字）→本体（最展开瞬间放慢）→定格（居中拉高，官方幕后口径）→结算回场（01 §3.1）。现仓 `cinematic.mjs` 已有死区+阻尼+zoom punch+环绕，缺的是「出画偏转至屏幕 1/3」「不完全回正」「定格 hold 段」三块（01 §5 差距清单 #3/#6/#8）。

### Q2 动画怎么做？（出处：02 档案 §一/§二/§三）

工业管线是一条流水线：建模→绑骨→蒙皮→动画来源（手 K/动捕）→**重定向**到各角色→引擎内状态机+混合树组织播放（02 §1.1）。重定向是「一套动作库服务全角色」的关键，前提是骨架标准化——**修订更正**：06 档案当时只在 3 份文件上亲测骨架一致（`compare-skeletons.mjs` 的 true×4 = 3 份文件 × 4 项布尔检查，06 §1.1②），「16 只完全一致」当时是全称命题以小样本背书；**修订轮已补跑 18 文件全量比对（16 只角色 + 2 个动画库），关节名顺序与集合全部一致、mismatched=0**（命令与输出见 §四.1），全称命题现在成立。「打起来有重量感」是一个配方：hitstop + 屏幕震动 + 方向性受击反应（additive 分层）+ 动画十二原则（预备/跟随/挤压拉伸）+ 音效同步（02 §2.4/§2.5）——注意 hitstop 各档案口径不一（02 判「已达标」），裁定见 §二.0。Three.js 侧完全可行：`AnimationMixer` + `clipAction` + `crossFadeTo` + `AnimationUtils.makeClipAdditive` 全是官方 API，本仓 `clips.mjs` 已走通「骨骼片段+时长缩放对齐命中帧+交叉融合」（02 §3.2/§3.6）。剩余差距在**引擎侧组织**：受击不按方向选片段且整段接管（`clips.mjs:27`）、移动只有单档 Walk 无连续混合——而 Jog_Fwd_Loop 已在库 A 与候选表第二位（但因「首位优先」机制永远播不到，clips.mjs:22，这正是步骤 7 要处理的「收进库 ≠ 自动生效」现成反例）。

### Q3 模型怎么动？（出处：05 档案 §2/§4 + 06 档案 §一/§二）

16 只全部自带 52 关节蒙皮骨骼（skins=1，实测解析 16 个 GLB 的 JSON chunk），但**内嵌动画为 0**——20 段动画（战斗 10 + 演出 10）在两个共享库 `naiwa_anim_lib.glb / naiwa_anim_lib2.glb` 里，由 `main.mjs:290/319-335` 的 `ensureAnimLibrary()` 分发给 16 只玩家 + 对手 + 选人页（05 §2.2）。共享的机理：three.js 的 mixer 按**轨道名字符串**（`mixamorig:Hips.quaternion`）绑定，骨架同名同序就能共用片段（06 §1.1、02 §3.4）。播放时 `clips.mjs:96-99` 把片段时长**缩放到游戏动作窗口**，保证战斗数值与命中帧不变；`crossFadeTo`（clips.mjs:100-139）做交叉融合防跳变。最大的演出空档不在骨骼在**个性**：程序化 6 种攻击风格（slash/thrust/slam/spin/peck/lash）在 clip 模式下整层死代码（`animation.mjs:121-133` 有 clips 即 return），`ACTION_CLIP` 候选表按优先级取第一个存在者——`Sword_Regular_A/B/C` 恒存在且排首位，于是 16 招在画面上全表现为同一套挥剑（05 §4.1-4.2；本轮亲验 clips.mjs:20-30）。**修订更正候选表「备胎」的实况**：Punch_Jab 已在库 2 与候选表中、却永远排不到（首位优先）；Melee_Hook 则**只有候选位、没有正段**——库 2 只收了收势 `Melee_Hook_Rec`，正段在官方 85 枚举里待收（05 §2.2、06 §2.5）。即「收进库 ≠ 自动生效」，生效开关见步骤 7②⑤。

### Q4 工业用什么软件？（出处：02 档案 §1.2 + 06 档案 §二/§三/§五；v2 重写为可执行结论）

对本项目真正要决策的只有三件事：①**绑骨与重定向已由官方链路完成**（自动绑骨 15 积分/只 + 官方 85 片段库重定向 6 积分/段，06 §2.1），不需要 Maya/MotionBuilder/Blender——02 §1.2 的软件分工表只是工业背景；②官方 85 段不够用时的免费扩容源是 **Mixamo 动画库**：官方绑骨产物骨架名就是 `mixamorig:*`，Mixamo 动画 FBX（Without Skin 档）免绑免映射直接烘，唯一硬约束是 Mixamo 只吃 FBX/OBJ/ZIP 不吃 GLB、须 Blender 中转（06 §三）；③**Anything World / Meshy / Tripo 等外部自动绑骨工具受台账红线约束**——`docs/ASSET-LICENSES.md:98`「3D 资产一律官方工具生成」，启用前须制作人改口径登记（06 §五.5）。16 只已全部绑骨完毕、当下不存在「绑不了骨」的情形，这套外部工具预案（含 Tripo 的 serpentine/aquatic 鱼形骨架）**当下零操作价值，仅存档备查**；Mixamo 路线的口径归属（动画素材 vs 3D 生成）也建议制作人确认一次（06 §五.5）。

### Q5 两个 3D 模型怎么战斗？（出处：03 档案 §1/§2 + 05 档案 §4.4）

本作打击链路 14 步已逐行对齐源码建档（03 §1 表）：命中帧→hitstop→受击片段→粒子→武器尖端特效→白闪拟声词→音效→相机拉近震屏→色散脉冲——反馈层数已经相当全。对照商业动作游戏的 9 层反馈模型，**唯一整层缺失的是 L4 受击击退位移**（九层表里 L1/L5 只是「有但弱」）；03 另按现状判读给出四处缺口 G1–G4：**G1 hitstop 档位争议**（现值 3/3/4/5 帧，本轮亲验 tuning.mjs:14-17；「行业 6–12 帧起步」是 03 口径——01/02 口径不同，裁定见 §二.0）；**G2 受击方无击退位移**——对手中招原地播动画，grep `knock|击退|弹开` 在 main.mjs/movement.mjs/tuning.mjs **0 命中**（05 §4.4，本轮复跑确认），而动捕行业口径是「打到了的体感 80% 来自守方反应」（**修订更正出处：03 §5.1**，非 §2.3）；**G3 武器相撞是伪判定**（见 Q7）；**G4 命中是单点时间判定**，无 active 持续窗，「武器扫过」的连续接触观感出不来（03 §2.1）。补上 G2 击退位移是「两个模型打不起来」旧观感的最高性价比解药（03 §6 路线表 #2）。

### Q6 震刀（弹刀）怎么震？（出处：03 档案 §3）

ZZZ / 只狼 / DMC5 三作模板一致：**预警分级**（可弹=金光/黄光，不可弹=红光/红「危」字，预警可读性高于一切特效）→ **判定窗极窄**（只狼 12 帧=200ms）→ 成功瞬间**四步同帧叠加**：「**停**」（时停/强 hitstop）→「**亮**」（武器相交点金白火花）→「**响**」（多层金属泛音 clang + BGM ducking 透出，Sekiro 用更高音高标记回合易主）→「**推**」（镜头微拉近 + 对手大硬直给出惩罚窗）（03 §3.4 共性表）。**修订更正本仓现状的表述**：弹反成功分支（main.mjs:1029-1046）没有显式 freezeT 赋值属实，但它经 `applyDamage(r.damage, "heavy")`（main.mjs:1040）**间接获得 4 帧顿帧与全套命中反馈**（applyDamage → main.mjs:648-653 设 freezeT）——初稿「无任何 freezeT」与 03 档案「无 hitstop，只播 playCounter」的口径都不准确；真正缺的是**专属的强时停/慢镜**（与普通 heavy 命中的 4 帧拉开层级）、**空间相交点火花**、与金属同族的弹反音（`playCounter` 是 UI 方波三连 1200/1600/2000Hz，audio.mjs:400-414）。此外三作模板的第一步「预警」在本仓有落地缺口：预警时长=前摇 0.25s（main.mjs:1231），03 §3.4 建议 0.35–0.5s，而 AGENTS 还挂着 **0.25/0.32 的未决调参冲突**——步骤 3① 落地前须制作人先裁决。

### Q7 武器怎么打到一起？（出处：03 档案 §4 + 05 档案 §4.3）

行业标准是把武器 blade 定义为**胶囊体（segment + radius）**，每帧从上一姿态**扫掠**到当前姿态防隧穿，相交时取最近点对作为火花定位点（UE Fest / computerBear / Unreal 论坛三源，03 §4.2）。本作现状是**伪判定**：命中时取攻击方武器尖端单点世界坐标出特效（`main.mjs:656-664`），且**对手根本没有武器**——`attachWeaponFor` 只在玩家队加载时调用（本轮亲验：仅 main.mjs:379 一处调用），弹反是否成立与双方武器空间姿态完全无关（纯计时器）。升级路径三级（03 §4.2）：①零成本版（弹反接触点=攻方 tip 与对手身体中轴连线中点）；②**标准版（推荐）**——武器加 base 节点构成 tip/base 线段，对攻守双方做线段-线段最近距检测（<0.12m 判相交，每帧 O(1)）；③完整版——胶囊扫掠 + active 窗绑定（动战斗基线，须制作人拍板）。顺带修 trail：本作拖尾是单点 14 帧 ribbon 靠「切线×视线」猜宽度方向（已踩过俯视退化 bug），补 base 锚点可根除（03 §4.3）。

### Q8 音效怎么弄、是什么样的？（出处：04 档案 §1–§4；v2 重写为可执行结论先行）

可执行结论四条：①**扩音效 = 加文件 + 加 key**——SampleBank 通道已就位（audio.mjs:60-91），工作量 ≈ 零架构改动，现仓 4 段 WAV 共 144,824 B 实测，扩到 12–16 条约 +600KB–1MB；②**duck 按事件分级**：格挡 0.35×0.35s / 命中 0.55×0.2s / 挥击 0.85×0.1s（04 §4.4）；③**弹反音必须与普通碰撞拉开层级**：clash_metal 提 pitch ×1.3 + 短高频 ring（Sekiro 铁律「更高更亮 = 回合易主」，04 §2.3）；④**对拍只给大招/连携末环**（吸附下一拍/半拍），常规连击保持 off-beat 错落——本仓 `_startLoop` 已是采样级精确 beat clock（128 BPM、一拍 0.46875s，audio.mjs:126 + music.mjs:59），只差暴露 `getBeatInfo()` 拍相位 API（04 §4.3）。背景知识（骨架已做对，物理细节见 04 §2.1 不再展开）：打击音是三段分层 whoosh→impact→tail；混音音量层级格挡 > 命中 > 挥击 > 喊话（04 §1.3）；本仓 `clash_metal.wav` 的 8 列失谐泛音已符合金属碰撞的声学本质；浏览器路径维持「离线 WAV 为主体 + 实时合成回退」双轨（04 §3）。ZZZ 官方从未公开 SFX 制作细节、也从未提「命中帧对齐节拍」——对拍标杆是 Hi-Fi Rush（04 §4.2）。

- **做什么**：一个共用模块给特肢个体加次级运动：蛋形 3 只（奶豆/奶蛋/豆奶）弹跳步（根节点抛物线+Spine 链 squash 0.85–1.1）+ 滚转攻击 + 果冻抖动受击（参照 ZZZ 邦布弹跳滚动语言）；长尾 3 只（奶猫/奶鼠/奶狗）+ 奶鱼尾鳍走 shader 顶点尾链（臀下顶点按 Hips 距离加权，正弦衰减+速度耦合，攻击瞬间增幅 ×3，**先在奶鱼上试点**——尾鳍离主干最远易分区）；奶兔双耳虚拟链；奶鸡翅刃（ribbon 挂翅端）+ peck 啄击。与 mixer 并行（mixer 写骨、本层写根 wrapper，避开 animation.mjs:122 的门禁）。**如实标注**：shader 顶点方案依赖「顶点到 Hips 距离加权」的**近似分区**（mesh 名全 `geometry_0` 无部位语义，05 §2.1 与 §四.3 已声明），且须与 NPR 描边壳同步（描边壳是同级 SkinnedMesh，不同步会「尾动了描边没动」）——先在奶鱼试点验证观感后再铺开。
- **动哪些文件**：新增 `src/game/extraLimbs.mjs`（或 `src/vfx/`，按线归属定）+ `src/game/tuning.mjs` 参数表；挂接在 main.mjs 角色装配处。
- **依赖研究**：06 §6.2/§6.3/§6.4/§6.5（每形态的参数与实现挂点都在）+ §七逐只表；05 §3 特例部位表。
- **预期观感**：最后 20% 的个性——蛋真的滚、尾真的甩、耳真的飘，「16 只是一个家族而不是 16 个皮肤」。**成本：1–2 天，可与步骤 7 并行试点。性能：shader 顶点偏移不增 draw call；若启用候补「受击点光源」，必须池化单实例（前向渲染每灯一份着色成本）。**

### 候补清单（研究已给方案、本轮未入主线）

- **连段取消表升级**：`CANCEL_FROM=0.72` 单阈值（combo.mjs:19）改逐段取消表 + 输入缓冲——绝区零手感差异大头（02 §五 #4）。

## 五、制作人会追问的六个问题（v2 新增：初稿漏答清单）

1. **积分预算与审批**：批 1 = 60 积分（10 段，清单见步骤 7①）；批 2 = 30–60 积分（5–10 段，OverhandThrow 列首位——奶茶招牌「热茶泼洒」依赖它）。合计 **90–120 积分**，须制作人审批后才能跑 retarget（初稿只列批 1 的 60，且「~60 收 20 段」是算术错误）。**审批动作是倒排关键路径**：审批不下，步骤 7 整体顺延。
2. **收口链与 11-19 倒排**：见 §二.0 与总纪律。要点：每批进提交版走 AGENTS §4 全链（登记→干净会话 E2E→重建→重录→重拍→双通道重部署→官网补提交，每轮 ≈0.5–1 天）；重录视频取自最近登记构建即有效，「改 src 未重录重部署」才会造成过期证据。倒排建议：第 1 轮（11-13～11-15）= 步骤 1+2+4 → 统一收口 + 官网补提交；步骤 7 积分审批立即发起，批 1 到账后（约 11-15～11-17）做映射与接线 → 第 2 轮收口；步骤 3/5/6 视剩余时间取舍；步骤 8 大概率放 11-19 后。
3. **E2E / 录像脚本重校成本**：改节奏/位置的步骤（1/2/7）各 +0.5 天重校与干净会话复跑；`capture-demo-video.mjs` 逐键时序与连段/QTE/克制判据可能要动（AGENTS 03:0x 教训在案）。
4. **性能预算**（现状基线：战斗屏 346 draw call / 177,722 三角面、heap 50→35 MB，AGENTS 22:0x 实测）：步骤 1/2/3/5 无 GPU 成本（参数/逻辑/DOM）；步骤 4 +600KB–1MB 下载与对应 PCM 内存；步骤 6 每帧 2 次线段检测 O(1)、trail 顶点数不变；步骤 8 shader 顶点偏移不增 draw call（风险在描边壳同步）；候补「受击点光源」须池化单实例；步骤 7 扩库 +~1MB 级动画资产，挂模型预取时序。收口时以 `scripts/measure-runtime.mjs` 复测 draw call/heap 不劣化为门槛。
5. **「爽」的验收口径**（初稿只有回归测试）：①同机位 A/B 实拍对照（改前/改后，复用 `scripts/capture-test-shots.mjs`）；②量化指标：连段接续时长（先例 0.26→0.19s）、顿帧毫秒数、击退位移米数；③制作人试玩 checklist（重量感/打击感/个性等 5 项主观打分）；④硬门槛：零 console 错误 + E2E 33/33（单会话）+ fps/heap 不劣化（`scripts/measure-runtime.mjs`）。
6. **受击窗断层**（03 §2.4 指出、初稿漏排）：0.22s 受击窗 < 段间隔会「抖一下又站直」——已并入步骤 2②。
