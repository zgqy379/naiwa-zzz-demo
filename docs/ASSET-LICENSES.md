## 1. 字段定义（与 `round2/audio_v1.md` 第十章、主程序 §3.7 `tools/pack` 一致，勿另立列）

| 字段 | 填写要求 |
|---|---|
| 素材ID | 与文件名一一对应，遵循 `audio_v1.md` §9.2 命名规范（如 `SFX_Feedback_BalanceTick_01`） |
| 素材名 | 人类可读名称 |
| 类别 | 枚举：`SFX / BGM / UI / AMB / 动作·动画 / 字体 / 其他`（动作库登记见下方「登记范围补充」） |
| 来源/URL | 自有填「自有重录 / 自有·程序化合成 + 生成脚本路径」；第三方填**原始素材页完整 URL**（不是搜索引擎结果页、不是聚合站首页）；生成式填**平台 + 模型 ID + 任务/生成记录 ID** |
| 授权(全名+版本) | 写全名与版本号，如 `Creative Commons CC0 1.0`、`CC BY 4.0`、`Suno Pro 订阅期内商用权（条款版本/生效日期）`；**禁止只写「免费」「可商用」「网上找的」** |
| 是否可商用 | `是 / 否 / 待验证`；赛事提交虽非商业发行，仍按「可商用」口径从严核验 |
| 是否需署名 | `是 / 否`；为「是」时必须同时填署名文本 |
| 署名文本 | CC BY 等需署名时，写可直接复制进 Credits / README 的完整文本；无需署名填 `—` |
| 是否随源码包分发 | `是 / 否 / 待验证`；这是加分项「项目源代码」的硬门槛，条款禁止再分发的素材填「否」并**从对外包排除** |
| 获取/生成日期 | `YYYY-MM-DD`；订阅制生成物须能覆盖该日期的订阅凭证 |
| 核验人 | 实名 / 角色名；谁核验谁负责 |
| 备注 | 循环点、采样率、变体编号、凭证存放路径、条款截图路径、风险提示 |

## 4. 署名文本模板（CC BY 等需署名时使用）

```
"<声音名>" by <上传者用户名> — <来源站名> — licensed under <许可证全名+版本> — <原始素材页完整 URL> — 修改：<是/否，改了什么>
```

- 需放进 README「素材授权声明」、项目报告书「素材授权声明」章节，并随源码包携带一份 `LICENSES/` 汇总（由主程序 §3.7 `tools/pack` 自动汇总本台账生成）。
- 一条素材一行，不得合并成「素材来自网络」这类不可追溯表述。
- **`tools/pack` 接线（与 lead-programmer-r2 对齐，字段无变动）**：`THIRD_PARTY_NOTICES.md` 逐项汇总开源组件许可时，第三方音频素材的条目从本台账「来源/URL + 授权(全名+版本) + 署名文本」三列直接取用；`LICENSES/` 汇总、以及「是否随源码包分发 = 否 / 待验证」与 §6 禁用清单构成的排除清单，同样由本台账生成。pack 硬门禁（本文件不存在或为空 → 退出码非 0、不生成 dist）已由主程序实现。
- 报告书 §10 固定口径（3D 资产一律官方工具生成，外部替代仅限官方能力缺口「音效/音乐/字体」且逐项登记，不使用绝区零音乐/角色配音/音效样本）与本台账一致，无需另立声明。

## 5. 登记流程（谁引入谁登记，5 步）

1. **获取即登记**：下载 / 生成 / 录制的**当下**填写来源 URL、许可证全名+版本、日期、模型 ID 或订阅档，不等到打包前补。
2. **逐条核验**：确认「可商用 + 允许再分发 + 是否需署名」三项；聚合平台必须追到底层模型条款；生成式必须留存订阅凭证与生成时间戳。
3. **生成署名文本**：需署名的按 §4 模板写好并随包携带。
4. **不确定即替换**：任何一项举证不全 → 换成自合成或 CC0，不带着疑点进对外素材包（`arch §7.2`）。
5. **分发前复查 + 冻结**：随源码包分发前复查一遍；冻结 tag 时台账一并冻结，冻结期零改动。

- ❌ 参考图 / 参考音频本身**不得随包分发**（`arch §7.2`：参考图不得随包分发）。
